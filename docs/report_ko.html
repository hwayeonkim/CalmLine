CalmLine 연구 노트

밤사이 프로토타입 구축 기록 · 2026-10-07 · 등록 마감 10/11 (D-4) · 제출 마감 10/18 (D-11)

공공 민원 상담사에게 전달되는 민원인의 목소리를 2초 늦추고, 그 사이에 폭언을 음소거하고 고함을 낮춥니다. 상담사에게는 사실을 빠짐없이 담은 차분한 카드를 건넵니다. 기획 단계의 설계를 실제로 동작하는 웹 데모와 버전별 실험으로 만들었습니다.

  • 처음 아이디어(미리 만든 문장 조합)는 사실을 절반 넘게 잃었습니다. 순수 템플릿 방식(v0)에서는 폭언 민원 중 해결에 필요한 정보가 모두 남은 경우가 44.6%뿐이었습니다. "어조는 템플릿이, 사실은 원문 발췌가" 맡는 하이브리드 구조로 바꾸자 83%로 올랐습니다.
  • 템플릿이 틀린 민원 유형을 단정하는 문제(하수 역류를 "소음 신고"로 전달)를 측정해 보니 29.5%였습니다. 분류 확신도가 높을 때만 유형을 말하게 바꿔 2.3%로 줄였습니다.
  • 실시간 음성은 "받아쓰기 속도"가 병목입니다. 논문의 LocalAgreement 스트리밍을 그대로 쓰면 2초 버퍼에서 폭언 단어의 49%가 들렸습니다. 최근 3초만 보는 2단계 구조로 바꿔 18%까지 줄였습니다. 실서비스는 Google Speech-to-Text 스트리밍으로 가야 합니다.
  • 작은 LLM(Gemma 1B)은 검증 없이 쓰면 위험합니다. 재작성 문장의 13.4%에 민원인이 말하지 않은 숫자(가짜 주소 등)가 들어갔습니다. 결정론적 검증을 통과한 것은 39%였습니다. Gemini로 같은 실험을 돌리려면 API 키가 필요합니다.

왼쪽은 민원인, 오른쪽은 상담사 화면입니다. 샘플 6개(난방·욕설, 포트홀·모욕, 성희롱, 위협, 정중한 민원, 정체성 공격)가 실시간 속도로 재생됩니다. 마이크로 직접 말해볼 수도 있습니다. 직접 확인한 결과는 다음과 같습니다.

난방 민원 + 욕설 CALM

욕설 3단어 음소거. 카드에는 "1820 Walton Avenue, apartment 2C, since Wednesday, three kids, 네 번째 연락"이 모두 남았고 욕설은 없었습니다.

위협 통화 ESCALATE

위협 구간 전체 음소거 + 감독자 경보. 위협 통화는 원문을 한 문장도 전달하지 않고 주소·연락 이력 슬롯만 넘깁니다.

정중하지만 화난 민원 PASS

원문 그대로 통과합니다. 다만 통화 첫 0.5초에서 1단어가 잘못 음소거되었습니다. 아래 한계 항목에 원인과 대안을 적었습니다.

상담사 통제권

보호 강도 3단(Shield / Calm voice / Raw), 상담 종료 요청 버튼, 원문 열람 감사 로그. 원문 음성과 전사는 evidence/에 봉인 보관됩니다.

어떻게 만들었나

기준선을 측정하고, dev 오류를 직접 읽어 원인을 찾고, 관련 논문의 방법을 적용한 뒤, 다시 측정하는 순서를 반복했습니다. 효과가 없었던 시도도 그대로 남겼습니다.

  1. v0

    제안하신 그대로의 기준선: 욕설 사전, 키워드 분류, 미리 쓴 문장 템플릿.

    "디테일이 빠질까?"에 대한 답이 숫자로 나왔습니다. 사실 보존은 44.6%였습니다.
  2. v1

    Jigsaw로 학습된 독성 모델(Detoxify toxic-bert)을 추가하고, 의도 분류는 bge-small 임베딩 최근접 원형(SetFit 방식)으로 바꿨습니다.

    감지는 98.8%로 올랐지만 "쥐들이 날 죽이네" 같은 표현까지 잡아 오탐이 12.8%가 되었습니다.
  3. v2

    condBERT(Dale 외 2021)식 토큰 마스킹을 응용했습니다. 머리말 템플릿으로 어조를 잡고, 폭언을 지운 원문 절을 "세부"로 덧붙입니다.

    사실 보존이 38.6%에서 81.9%로 뛰었습니다. 대신 지운 자리의 잔여물("You sound… Come lap")로 누출이 21.7%가 되었습니다.
  4. v3–v4

    Waseem 외(2017)의 지향성(directed) 구분을 적용했습니다. 모델만 잡은 플래그는 상담사를 향한 2인칭일 때만 인정합니다. 렌더링한 뒤 다시 검사하고, 슬롯이 없는 폭언 절은 통째로 버립니다.

    오탐 4.3%, 누출 8.4%.
  5. v5–v6

    모델을 unbiased-toxic-roberta로 교체하고, 위협에 대해 NLI 제로샷 안전망(Yin 외 2019)을 추가했습니다.

    우리 테스트셋에서는 오탐만 늘었습니다(실패). 다만 외부 Civil Comments의 위협 재현율은 29%에서 73%로 올라 백본은 유지했습니다.
  6. v7–v8

    Gemma에게 "위험을 걱정하지만 폭언은 없는" 민원 98건을 쓰게 했습니다(다른 저자 효과). 그 결과 "누가 죽을까 봐 걱정돼요"를 자해로 잡는 패턴 버그를 찾았습니다. 과장 표현(Troiano 외 2018)·걱정 맥락 필터를 추가했습니다.

    하드 네거티브 오탐 10.2%에서 1.0%로.
  7. v9–v10

    확신도 0.70 이상일 때만 민원 유형을 단정합니다. 라이브 데모에서 슬롯이 욕설을 그대로 실어 나르는 버그("the fourth fucking time")를 발견해, 슬롯을 마스킹된 텍스트에서 추출하도록 고쳤습니다.

    유형 오단정 11.4%에서 2.3%로, 누출 7.2%.
  8. v11 †

    테스트 오류를 사후 분석했습니다. 독성 모델이 "garbage", "rats" 같은 민원 주제어를 모욕으로 읽고 있었습니다. Dixon 외(2018)의 정체성어 마스킹을 응용해 주제어를 중립어로 바꾼 뒤 채점합니다. 위협 통화는 슬롯만 전달합니다.

    보호 98.8%, 오탐 2.1%. 테스트를 본 뒤 만든 버전이라 낙관적인 수치입니다.

음성 실험

고함 감지와 어조 정규화 (CREMA-D, 학습에 없던 화자 30명)

eGeMAPS(Eyben 외 2016) 계열 운율 특징을 화자 기준으로 정규화하자 분노 감지 AUC가 0.921, 중·고강도 분노 재현율이 100%였습니다. 계산은 클립당 8.5 ms입니다. 지연 버퍼 덕분에 미리 볼 수 있는 압축기가 고함 구간을 11.8 dB 낮추고, 평상시 말은 0.3 dB만 건드립니다.

Whisper의 욕설 회피

Whisper는 욕설을 덜 받아씁니다. 욕설 어휘를 담은 초기 프롬프트를 주면 욕설 토큰 인식률이 92.0% → 95.6%(base.en)로 올랐고, 정상 통화 30건에서 욕설 환각은 0건이었습니다. 다만 디코딩이 느려져 실시간 1차 처리에서는 끄고, 2차 카드 생성에만 씁니다.

1차 받아쓰기 방식RTF누출 @1.5초누출 @2초누출 @3초정확도 한계 @4초오음소거 초/정상 발화
LocalAgreement, base.en (Macháček 외 2023)1.1266.949.240.6—0.08
3초 창, base.en1.1841.731.926.0—0.03
3초 창, tiny.en (채택)0.3921.718.117.716.90.18
3초 창, tiny.en + 창 끝 확인0.3825.620.5—18.10.13

RTF가 1을 넘으면 노트북 CPU에서 받아쓰기가 실시간보다 늦어지고, 누출의 대부분은 그 지연에서 나옵니다. tiny.en은 실시간보다 2.5배 빠르지만 정확도 한계(@4초 16.9%)가 남습니다. 이 한계는 오인식과 감지 누락에서 옵니다. Google Speech-to-Text 스트리밍으로 바꾸는 것이 다음 단계입니다. 어댑터 코드는 calmline/audio/google_stt.py에 작성해 두었지만, 인증 정보가 없어 실행해 보지는 못했습니다.

검증은 세 가지를 확인합니다. 재작성 문장이 폭언이 아닐 것, 원문에 없는 숫자가 없을 것, 원문에 없는 주장("전에도 전화했다")이 없을 것. Gemma 1B는 탈락이 많아 사다리 구조를 이기지 못했습니다. Gemini 경로는 코드로 연결만 해 두었습니다. 대회 요건(Gemini/Gemma 사용)은 현재 Gemma로 충족되지만, Gemini Flash 계열로 같은 표를 다시 뽑아야 심사용 근거가 됩니다.

정직한 한계

  • 같은 저자 편향. 테스트셋과 욕설 사전을 모두 제가 썼습니다. 그래서 사전 기반 수치는 낙관적입니다. 이를 보정하려고 외부 Civil Comments(위협 재현율 v4 19% → v11 72%), Gemma가 쓴 하드 네거티브, CREMA-D를 따로 보고합니다.
  • 음성 데이터가 TTS입니다. macOS say로 만든 음성이라 실제 분노 운율이 없고, 실제 고함 속 욕설 인식률은 더 낮을 것입니다. 팀원 녹음 60건이 필요합니다. 데모의 마이크 녹음이 evidence/에 저장되므로 녹음 도구로 바로 쓸 수 있습니다.
  • 위협 통화의 정보 손실. 안전을 우선해 위협 통화는 슬롯만 넘기므로 합성 dev 사실 보존이 88%에서 82%로 떨어졌습니다.
  • 통화 시작 오음소거. 정상 통화 첫 단어가 잘못 음소거되는 경우가 있습니다. 창 끝 확인 정책을 켜면 오음소거가 30% 줄고 누출이 2.4%p 늘어납니다. 지금은 보호를 우선해 꺼 두었습니다.
  • 지연 수치는 Apple M5 노트북 기준입니다. Cloud Run CPU 환경은 다를 수 있습니다.
